二、診斷面板：列入需求與不列入需求

判斷原則：會拉高 LCP／INP／TTFB、且全站重複出現的才請列入本次開發。PSI 預估節省時間實際會低於字面數字，但排序仍可靠。

PSI 項目 典型數字 實務判斷 請貴公司處理方式
Render-blocking requests 手機 6–12.6s；電腦 1.3–2.3s 必須處理 合併並延後 Drupal／Barrio 全站 CSS。首屏不該載入 book、toolbar、webform、tablesort 等後台元件樣式。
Improve image delivery 首頁桌機 1,167 KiB；捐款手機 994 KiB 必須處理 主視覺與捐款圖用 picture／srcset、正確尺寸、preload LCP，slider 不要一次載入全部投影片。
LCP request discovery / breakdown 首頁與列表頁皆出現 必須處理 LCP 圖不要 lazy；加 fetchpriority=high；減少 LCP 前的 CSS／字體依賴鏈。
3rd parties + unused JavaScript 未使用 JS 約 232–255 KiB 必須處理 GTM、兩組 gtag、Facebook Pixel、Matomo、LINE 標籤改延遲載入並整併。這直接關係 INP 198ms 的安全邊際。
Network dependency tree 關鍵路徑上數十個 CSS 必須處理 與 CSS 合併同一案。現況是 Drupal 10 + Bootstrap Barrio 把元件 CSS 逐一掛在 head。
TTFB（實測） 手機 1.1s／電腦 0.9s 必須處理 匿名頁快取、CDN、HTML 壓縮。這是實測裡唯一明確「需改善」的指標。
Noto Sans TC 字體 4 個字重、20+ 個 woff2 應該處理 自架並 subset；正式頁面通常 400／700 即可；preload 主要檔，減少檔案數。
Forced reflow jquery.min.js、drupal.init.js 應該處理 非首屏 jQuery 延後；避免文件載入階段讀 layout。
Layout shift culprits（實驗室） 首頁手機 CLS 0.537 應該處理 實測 CLS 已是 0。優先修字體與 slider 高度，logo.svg 補寬高。不要為實驗室 CLS 大改版型。
Avoid enormous network payloads 約 2–4.7 MB 應該處理 隨圖片、字體、第三方腳本下降。不必單獨當專案。
Long main-thread tasks / TBT 7–15 個長任務 應該處理 第三方與 Drupal JS 延後即可帶動。活動頁與年度報告桌機 TBT 偏高。
Unused CSS 約 154–192 KiB 可隨 CSS 合併處理 不要重寫 Bootstrap。用 Drupal library 依賴拿掉未用元件即可。
Minify CSS / JS 17–36 KiB / 3–34 KiB 不必當需求 節省太小。aggregation 開了會自然縮小。
Legacy JavaScript 21 KiB 全部來自 fbevents.js 不必處理 Facebook 官方腳本。應延後或評估是否還要 Pixel，而不是改寫。
Efficient cache lifetimes 176 KiB fbevents、matomo、lt.js 不必強求 第三方快取期限無法完全控制。自有靜態資源確認長期快取即可。
Optimize DOM size 多數頁有出現 低優先 除非節點數極端，對 CWV 影響小於 CSS 與第三方。
